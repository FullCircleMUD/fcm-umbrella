# macOS only. Apple's system SQLite drives sqlite3_initialize() through
# libdispatch, which does not survive the fork `evennia start` uses to
# daemonize — the server then deadlocks on its first query, silently, with
# nothing in any log. sqlean.py ships its own statically-linked SQLite, and
# the demo settings swap it in, gated on darwin.
sqlean.py; sys_platform == "darwin"

# The libraries, none of which are on PyPI. Editable from the local checkouts
# so a fix found while testing is a save, not a reinstall. Deepest first:
# nothing in evennia-scaling imports the logging extension or the cascade, but
# the archive and the bus depend on both.
#
# Paths are relative to this file, so install from src/:
#     ./venv/bin/pip install -r requirements.txt
-e ../libraries/evennia-logging-extension
-e ../libraries/evennia-database-cascade
-e ../libraries/evennia-portal-multiplex
-e ../libraries/evennia-archive
-e ../libraries/evennia-message-bus
-e ../libraries/evennia-scaling

# Ships functions only — no settings, no startup hook, no migrations. Depends
# on evennia-logging-extension, already above.
-e ../libraries/evennia-targeting

# Calendar reads one optional setting. Equipment needs a slot enum and an
# identity attribute, both declared in the game's libraries/ folder. The LLM
# service brings openai in from PyPI and wants a prompt folder.
-e ../libraries/evennia-calendar
-e ../libraries/evennia-equipment
-e ../libraries/evennia-llm-service

# Hunger and thirst. Needs a stage enum per meter and two clock intervals,
# none of which it can invent; the stages are in the game's libraries/ folder.
-e ../libraries/evennia-survival

# Conditions as ref-counted flags, and named effects over them. Needs a
# catalogue of both, declared in the game's libraries/ folder.
-e ../libraries/evennia-effects-conditions

# On-chain item and currency ownership. Brings in xrpl-py, httpx and requests.
# Needs an xrpl_seed app of the game's own — the library ships schema only,
# and which currencies exist is game content.
-e ../libraries/fcm-xrpl

# One interface over a local checkout and a GitHub repo, so a consumer reads
# YAML the same way either way. A dependency of ai-memory, useful alone.
-e ../libraries/evennia-yaml-reader

# Lore and interaction memory as embeddings. Brings in numpy, pgvector and
# psycopg; needs an embeddings endpoint and a lore repository.
-e ../libraries/evennia-ai-memory

# Both read YAML content repos through evennia-yaml-reader above, and both
# confine their work to one instance when evennia-scaling is present.
-e ../libraries/evennia-mob-spawner
-e ../libraries/evennia-world-builder

# Subscription payment over XRPL. Needs fcm-xrpl above — the account mixin
# pairs with its wallet_address, which every durable subscription query keys
# on. Plans are seeded from the game's own libraries/ folder.
-e ../libraries/fcm-subscriptions
