Memory is for behaviour notes — how to work. A deferred decision or "I'll review it later" is a backlog item, and Tim keeps those on his own list.

**Why:** a "review later" item was saved as a memory (2026-10-03); Tim: "that's not a behaviour note … that's a backlog item for a to-do list."

**How to apply:** when something is parked, say so in the reply and stop. Don't write it to memory unless Tim asks.

The same goes for practices tied to one stage of the work — a zone's content rules, a block's layout. They go stale as the work moves on, and every entry pushes the index toward compaction (2026-10-19, Tim: "a self-fulfilling bloody cycle"). Save only what stays true across the project.
